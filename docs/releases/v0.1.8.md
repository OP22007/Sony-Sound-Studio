# v0.1.8 — Experimental macOS control and a Linux reconnect fix

## macOS

- macOS can now open a control connection to Sony and OnePlus headphones. It is experimental and has not been tested on a Mac with real headphones.
- All Bluetooth objects stay on one owner thread. A write that times out or is cancelled ends the connection instead of being retried, so a late transmission is never reported as success. Settings still show as changed only after the headphone reads them back.
- Service records come from a fresh Bluetooth service query on every connect, and the callback delegate is kept alive while the channel closes.
- macOS asks for Bluetooth permission the first time. Active audio-output detection and automatic listening are still Windows-only.

## Linux

- A headphone that closes the control link while its settings are read, as 0.1.7 added reads that can trigger this, needs a few seconds before it accepts the service again. The reconnect now tries up to five times, two seconds apart, instead of failing the whole connection at once.
- The connection error now names the reason: a missing service record, or the operating-system error from the Bluetooth connect.

## Verification and limitations

Windows, macOS and Linux CI is expected to pass. The macOS transport type-checks for both Apple architectures and its worker tests pass on Windows, but a real Bluetooth permission prompt, service query, connection, read and write need a Mac and headphones. The Linux fix follows a reported 0.1.7 regression on Ubuntu and has not been confirmed on that machine.

macOS builds are not Apple-signed or notarized, and the Windows installer has no Authenticode publisher signature.

## Updating

From **v0.1.2** or later, open **App settings → App updates → Check for updates**, or use the update banner, then choose **Install & restart**. DEB/RPM users install the new package manually; Linux in-app updates require AppImage.

Report issues through the repository's tester-feedback template with your OS, app version and headphone model/firmware.
